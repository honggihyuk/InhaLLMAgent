## 1-2주차: 인프라 및 데이터 기초

**만든 것**
- `Document / Chunk / SearchFilter` 모델, 문서 ID 해시로 중복 제거
- 수집기: 로컬 녹취록(json/jsonl/txt), SEC EDGAR(API 키 불필요, User-Agent에 연락처 필수, 초당 10회 이하), 야후 파이낸스 RSS, JSONL 뉴스
- HTML → 텍스트 변환(표준 라이브러리만 사용)
- 청크 분할(문단·문장 단위 + 겹침, 메타데이터 머리말)
- 임베더 3종, FAISS 저장소(필터 검색, 삭제, 저장/로드), 검색기, FastAPI 검색 API, CLI(`ingest / search / serve`)

**검증**: SEC·RSS는 `httpx.MockTransport`로 응답을 흉내 내 테스트했습니다. 종목 필터, 기준일 필터, 재수집 시 중복 없음, 저장 후 재로드 동일 결과, API 전 엔드포인트를 확인했습니다.

## 3-4주차: LLM 백엔드 및 에이전트 프레임워크

**만든 것**
- `LLMClient` 인터페이스, Claude 백엔드(스트리밍, `output_config.effort`, 거절 시 `fallbacks: "default"`, 거절 응답은 오류로 표면화), vLLM 백엔드, Mock/Scripted 백엔드
- `QuantAgent`: 검색 → CoT 프롬프트 → 신뢰도·JSON·코드 추출 → 메모리 기록. 프롬프트 첫 줄 `TASK_KIND:`로 작업 종류 표시
- `IdeationAgent / ImplementationAgent(수정 기능 포함) / EvaluationAgent`
- `SharedMemory`(라운드, JSONL), `MessageBus`(유형별 메시지, 브로드캐스트, 상관 ID)
- 팩터 지표: IC, Rank IC, ICIR, t값, 롱숏 샤프, 최대낙폭, 회전율
- 합성 시장 데이터 생성기(단기 반전 신호를 심을 수 있음)

**검증**: Claude 요청 형식(모델, effort, fallback 베타, thinking·temperature 미전송)을 가짜 클라이언트로 확인했습니다. 실제 Claude 호출은 API 키와 비용 때문에 하지 않았습니다.
심은 반전 신호는 IC 0.05 이상·t 3 이상으로 찾고, 순수 랜덤워크에서는 |IC| < 0.03임을 확인했습니다.

## 5-6주차: 알파 생성 파이프라인

**만든 것**
- `AlphaGenerationPipeline`: 아이디어 → 구현 → 샌드박스 → 편향 검사 → IS/OOS 평가 → 비용 차감 백테스트 → 직교화 → 검토 → `FactorLibrary`
- 샌드박스(`sandbox/`), 예측 편향 탐지(정적 패턴 + 절단 테스트), 알려진 팩터 라이브러리와 횡단면 직교화
- 벡터화 백테스터(체결 지연, 비용, 리밸런싱 주기, 리스크 오버레이 연결점), Backtrader 어댑터
- 텍스트 신호: 문서마다 LLM이 sentiment/guidance/risk를 채점 → 시점 기준 감쇠 패널
- 문서 톤이 이후 수익을 예측하도록 만든 합성 데이터셋, 데모 스크립트

**검증**: 정적 검사로 못 잡는 전체 표본 정규화 누수를 절단 테스트가 잡는 것, `shift(-1)` 코드를 수정 요청해 고치는 흐름, 고칠 수 없는 코드는 `invalid` 처리되는 것을 확인했습니다.
오프라인 데모(50종목 × 300일)에서 텍스트 팩터만 채택되고(OOS IC 0.139, 순샤프 5.6), 반전 계열은 알려진 팩터와 상관 0.9 이상, `vwap_gap`은 회전율 1.6으로 비용 후 손실이라 기각됐습니다.

## 7-8주차: 검증 및 운영 환경 강화

**만든 것**
- `historical_reruns`: 매 기준일마다 그 날까지의 데이터로 파이프라인 전체를 다시 실행하고, 운용 중인 팩터를 다음 달 데이터로 채점
- 워크포워드 검증(라벨 겹침 제거), Newey-West 스패닝 테스트, 둘 다 채택 기준에 추가
- `RiskOverlay`: 종목 상한, 섹터 중립, 총·순노출, 섹터 총노출 한도
- 모니터링: 롤링 IC, 예측 기간별 IC 곡선과 반감기, 상태 판정(healthy/decaying/dead), HTML 대시보드
- 실제 가격 로더(CSV, yfinance), 합성 섹터 매핑

**검증 결과** (합성 50종목, 440거래일, 21일마다 11회 재실행)

| 기준일 | 새로 채택 | 운용 팩터 수 | 다음 달 IC |
|---|---|---|---|
| 2024-09 ~ 11 | 없음 | 0 | |
| 2024-12-18 | sentiment_drift | 1 | 0.074 |
| 2025-01 ~ 03 | | 1 | 0.006, 0.129, 0.036 |
| 2025-04-15 | guidance_surprise_unpriced | 2 | 0.082 / 0.077 |
| 2025-05 ~ 07 | | 2 | 0.139·0.141, -0.011·0.008, 0.161·0.073 |

운용 팩터-월 12개 중 11개가 양수, 평균 0.076입니다. 대시보드는 guidance 팩터를 최근 IC 하락으로 `decaying` 표시했습니다.

## 9-10주차: 다중 에이전트 강화

**만든 것**
- `ManagerAgent`: 목표 분해, 전문 분석가 배정(TASK 메시지), 결과 종합. 계획이 깨지면 목표 하나를 과제로 대체
- `PortfolioAgent`: ICIR 가중 결합, 리스크 오버레이, 변동성 타기팅(전일까지 실현 변동성 사용, 최대 2배). LLM 검토는 0~1 배율만
- `RiskAgent`: VaR95/CVaR95, 20일 변동성, 낙폭, 총·순노출, 최대 비중, HHI, 섹터 순노출. 위반 시 ALERT 방송과 축소, 낙폭 15% 초과 시 중단
- `EnsembleDecision`: 가중 투표, 실현 초과수익 기준 적중률로 가중치 갱신, 동점이면 보유. `AnalystAgent`의 LLM 투표(근거 없으면 보유)
- `ResearchTeam`: 위 전부를 하나의 버스와 메모리로 연결

**검증**: 정확한 투표자와 무작위 투표자를 섞으면 앙상블이 정확한 쪽 가중치를 키워 후반부 결정이 90% 이상 일치합니다. 포트폴리오 실현 변동성이 목표 10% 부근(5~20%)에 들어오는지, 리스크 에이전트의 축소·중단·경보, 팀 전체 실행에서 메시지와 메모리 기록이 남는지 확인했습니다.

## 11-12주차: 프로덕션 배포

**만든 것**
- 스트리밍: 브로커 추상화(인메모리 / confluent-kafka), 문서 프로듀서, 소스 폴러(한 소스가 실패해도 계속), 최소 1회 전달 수집 컨슈머, Kafka 경유 MessageBus
- 통제: LLM 회로 차단기와 대체 모델, 거래 차단기(래치), 킬 스위치, 팩터 일시정지, 운용 배율(0~1), 승인 대기열
- 감사: 해시 체인 JSONL, LLM 호출 기록(프롬프트는 해시만), 규제 보고서(JSON / Markdown)
- 모의 운용 루프(`ops/live.py`), 운영자 API(`/ops`, `X-Operator` 필수)
- API: 인덱스 원자적 저장과 자동 재로드, CLI `serve --with-ops / consume / poll`
- 배포: Dockerfile, docker-compose(Kafka KRaft), 쿠버네티스(Strimzi Kafka·토픽, API+HPA, 단일 작성자 컨슈머, 폴러, 야간 연구 CronJob, restricted 보안, 기본 차단 NetworkPolicy)

**검증**: 중복 전달과 커밋 전 중단 후 재전달에도 색인이 한 번만 되는 것, 감사 기록 한 줄을 고치면 그 위치에서 검증이 실패하는 것, 차단기 상태 전이(closed → open → half_open → closed),
승인 전에는 큰 주문이 보류되고 승인 후 반영되는 것, 킬 스위치 시 전량 청산을 테스트했습니다. 모의 운용 데모(30종목, 15일)는 감사 레코드 409개, 무결성 검증 통과였습니다.
Kafka 클러스터와 쿠버네티스에 실제로 배포해 보지는 않았고, 매니페스트는 YAML 구문만 검증했습니다.

## 개발 중 발견해 고친 문제

| 문제 | 영향 | 해결 |
|---|---|---|
| `library or FactorLibrary()` | 빈 라이브러리가 거짓으로 평가돼 새 객체로 바뀌고 파일 저장이 안 됨 | `is not None` 비교로 변경 (메모리·샌드박스도 동일) |
| 스패닝 테스트를 OOS 구간에서만 계산 | 모멘텀(120일)이 전부 결측이라 t=0, 모든 팩터 기각 | 알려진 팩터 수익은 전체 기간에서 계산 후 OOS로 자름 |
| 앙상블 동점 처리 | 매수·매도 동점일 때 매수 선택 | 1위 동점이면 보유 |
| 리스크 오버레이 | 상한 자르기 후 섹터 중립이 깨짐(섹터 순노출 7%) | 큰 쪽만 줄이는 방식으로 정확히 맞춤 |
| 평활한 감성 팩터의 부호 반전 | 10일 평균이 드리프트 종료 후 반전 구간까지 끌고 감 | 감쇠된 원 신호 순위 사용 (모의 템플릿) |
| 고회전 팩터 채택 | `vwap_gap`이 비용 후 손실인데 IC만으로 통과 | 비용 차감 OOS 샤프 > 0 조건 추가 |
| 과거 재실행에서 같은 팩터 재채택 거부 | 중복 판정으로 운용 팩터 추적 누락 | 매 기준일 운용 집합 = 지금까지 채택된 전체 |
| 검증 속도 | 과거 재실행 9분 | IC 계산 벡터화, 알려진 팩터 캐시, 전체+절단 데이터를 한 프로세스에서 실행 (약 6~7분) |
| Windows CRLF | 파이썬으로 고친 파일에 문자열 리터럴 깨짐 | `core.autocrlf false`, 편집 도구로 수정 |

## 아직 하지 않은 것

- 실제 Claude API 호출: API 키가 필요하고 문서마다 1회 호출이라 비용이 듭니다. 문서가 많으면 Message Batches API로 바꾸는 것이 좋습니다.
- 실제 SEC·뉴스 데이터와 실제 가격으로 돌리기: SEC 연락처 이메일과 종목·기간 선정이 필요합니다.
- 실제 Kafka·쿠버네티스 배포와 부하 테스트
- 브로커 연동(실주문). 현재는 모의 운용만 합니다.
- 샌드박스 속도: Windows에서 프로세스 기동이 약 3초라 대부분의 실행 시간을 차지합니다. 운영 환경에서는 컨테이너 단위 워커 풀을 검토할 만합니다.
